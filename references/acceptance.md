# 验收顺序与故障判断

| 层 | 验收证据 | 常见误判 |
| --- | --- | --- |
| 应用与依赖 | 从独立网络登录；读写对象；重启后数据仍在 | 容器 Running 就宣称可用 |
| 设备 | 从实际 LobeHub 设备上下文执行只读命令 | SSH shell 能执行就算通过 |
| GitHub | 试点安装范围；签名事件确实推进对应任务 | 授权 UI 显示已连就算有仓库写权 |
| 独立审查 | 单独会话核对精确候选；有缺陷才修复并复审 | 把开发者自审或错版本输出算成独立通过 |
| 部署 | 候选/合并的 CI、部署版本、真实页面和健康接口 | 合并成功就算发布成功 |
| 回执 | 匹配运行的最终结果实际进入原会话，记录发送状态 | 超时后人工查询算自动送达 |

从试点发一条全新、能在页面观察的低风险需求，按授权做到开发、审查、CI、合并、测试部署与回执。记录 request/topic/operation、审查候选、PR、CI 运行、合并及实测版本、接收证据和人工介入。没有触发修复、断网或主机重启时明确标未验证。测试部署用独立环境，保留上一可用版本和数据；失败时先查已更新范围及数据兼容，再按明确目标回滚并复验，不清卷。

遇到故障先区分：已确认未执行（修前置再继续）、已经执行但结果未知（查原 ID）、部分执行（核对真实状态再决定继续/回退）。将安装/更新、DNS、GitHub、桥与业务发布的回滚点分别记录。
