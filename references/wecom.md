# 企业微信接单与 Claude Code

先确认当前版本的原生渠道能力。若没有所需企业微信智能机器人能力，用 [企业微信智能机器人 Node.js SDK](https://github.com/WecomTeam/aibot-node-sdk) 的长连接实现自建桥；它独立于 LobeHub Bot 列表。用试点智能机器人创建长连接配置，Bot ID/Secret 仅存服务端，先允许明确成员的单聊，再按需求扩展会话范围。核对从机器人实际收到的事件类型、发送者和会话标识，先验证授权成员和未授权输入的处理。

桥的可移植实现合同：

1. 收到事件先按机器人/消息 ID 去重，校验发送者/会话和任务目标。收到后通过该版 LobeHub API 或 CLI 提交，记录返回的话题和 operation 标识。绑定成功后发短确认，再由后台轮询或事件驱动跟踪。同一试点话题可以先串行，避免两个运行互相覆盖。
2. 用持久存储记录 `received → waiting → sending → delivered`，并留 `unknown` 供对账。存入话题和 operation 后重启应继续查该运行。只在匹配 operation 已结束且有最终结果时发回执；部分回复和旧任务文本不可代替最终结果。查询失败可按退避恢复；无终态设可观察的告警和解除阻塞策略。
3. 完成后用 SDK 支持的主动发送（如 `sendMessage`，按版本确定单聊/群聊目标），不依赖原回调帧的有效期。按 SDK 发送回执确认；保留最终结果链接。提交或推送超时可能已生效，标记结果未知并按原标识对账；没有幂等保障时不盲目重发。此设计不保证端到端精确一次。服务与数据库放持久位置，受 systemd 或等效监督。
4. 验收：真实短消息、超过旧回复窗口的真实长任务、桥在 waiting 时重启后自动送达；另做重复入站、错误 operation、发送结果未知、授权失败的隔离测试。收件界面实际显示和持久状态要一起核对。

独立审查若用 [Claude Code CLI](https://code.claude.com/docs/en/cli-reference)，以运行设备的实际服务账号准备独立、持久的认证目录。通过官方登录流程在该目录认证；绝对路径包装器指定选定版本的 CLI 与 `CLAUDE_CONFIG_DIR`，服务进程也使用同一目录。用实际设备执行最小真实审查，核对版本、目录与只读差异输出。交互式 shell 的登录成功或 `auth status` 都不足以证明真实调用。裸 `claude` 可能走另一安装和认证目录，尤其经登录 shell 重排 PATH 时。查实际执行路径后再判断是否订阅过期，不输出凭据。审查用独立会话和候选 worktree；仅靠文字约束不等于 OS 隔离。

绝对路径包装器示意（替换为实际路径并由服务账号持有；认证目录应限制为该账号访问）：

```sh
#!/bin/sh
export CLAUDE_CONFIG_DIR=/var/lib/agent-runner/claude-auth
exec /opt/agent-tools/claude-pinned "$@"
```

首次按 `lh message send --help` 或选定 API 验证是否能获得话题及运行 ID、如何读取该运行的最终消息；先让桥输出脱敏的运行标识与状态，再接入长任务。若选定版本不暴露稳定运行标识，先停在短任务验证，不能仅凭话题“最新回复”推送交付结果。
